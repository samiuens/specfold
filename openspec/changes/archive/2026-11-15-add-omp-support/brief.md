## Wish

"Can we make specfold compatible with omp?" Make Specfold work in omp (oh-my-pi) with full parity: the same workflow, roles, hooks and guards that Claude Code gets, opt-in per repository.

## Decisions

| # | Question | Answer | Source |
| --- | --- | --- | --- |
| Q1 | How much of the agent layer does omp get? | Full parity: subagent roles, session hooks, rendered permissions, parallel sf-apply on omp's isolated tasks, and the actor prefix. AGENTS.md and the sf skills already load in omp unchanged. | user |
| Q2 | Where do omp's role definitions come from? | Generated by the CLI from `.claude/agents/*.md` into `.omp/agents/*.md`, so the roles keep one source, like `specfold agents sync` does for skills. | user |
| Q3 | Does every repository get the omp files? | No, opt-in: a new `tools:` list in `specfold.yaml` with the ids `--tools` already uses, for example `[agents, claude, omp]` (`agents` always present), set by `specfold init --tools` and `specfold migrate install --tools`. `omp` is left out of the tool list passed to `openspec init`. The ids were confirmed in a second question after the plan approval. | user |
| Q4 | How do the Claude Code hooks reach omp? | One shipped TypeScript hook factory in `.omp/hooks/pre/` calls the existing `specfold hook claude-*` subcommands, so the logic stays in the CLI. The stop check uses omp's main-session `session_stop` event and blocks with the findings as the reason, as Claude Code's Stop hook does; this replaced a follow-up message from `agent_end` after the task 1.1 spike found the event. | user |
| Q5 | Which models do the generated roles use? | Claude aliases map to omp roles: `haiku` to `@smol`, `sonnet` to `@default`, `opus` to `@slow`; `effort` maps to `thinking-level`. | user |
| Q6 | Does omp get a planner role? | No. omp subagents run headless and cannot ask the user, so omp plans in the main session with the `sf-plan` skill. | user |
| Q7 | Do the read barriers reach omp? | No; omp has no deny-read rule, and the open backlog item `/backlog/read-barriers-for-other-agents.md` keeps the idea. | user |
| Q8 | Which actor prefix does an agent write when one repository is used from both tools? | The CLI detects that it runs under omp from the environment and uses `omp/`; `actors.agent_prefix` stays the fallback. | user |
| Q9 | Where do omp's settings go? | `.omp/config.yml`: `bash.patterns` from `permissions`, plus `task.maxRecursionDepth: 1` and the task isolation settings sf-apply needs. Keys Specfold does not own stay unchanged. The subagent limit stays personal: `.omp/config.yml` is committed, so sf-apply on omp dispatches at most the `specfold parallel show` limit per batch instead of writing `task.maxConcurrency`. Revised in a second question after the plan approval. | user |
| Q10 | What happens to the duplicate `openspec-*` skills omp lists (different real copies in `.agents/skills` and `.claude/skills`, written by `openspec init`)? | Out of scope; kept as a backlog item. | user |

## Out of scope

- Read barriers for omp (`/backlog/read-barriers-for-other-agents.md`).
- The duplicate `openspec-*` skill copies `openspec init` writes into both skill folders (new backlog item).
- A planner role for omp.
